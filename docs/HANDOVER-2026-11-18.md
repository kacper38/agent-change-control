## What a cloud session can do here

Each line was measured in this session on 2026-11-17 and 2026-11-18. The session ran in the permission mode
"auto" of Claude Code on the web.

1. **The repository's hooks run.** The guard of the session's checkout judged every call; its decision log
   holds the lines.
2. **An ask stops the session.** The harness turns a hook's `ask` into an approval request in the owner's app
   and waits. Second scratch write: asked 22:02:49 UTC, closed unanswered at 06:51 UTC when the next message
   of the owner was delivered; the call did not run.
3. **One asked call ran without an answer.** First scratch write: asked 21:52:23 UTC and waited. At 21:58:56
   the session's worker was restarted, the same call was judged again (`ask`, 21:58:57) and ran in the same
   second. The harness recorded the decision as `accept`, source `config`, reason `mode`, so by its record the
   mode let it through and no person did. The file was a scratch note outside the repository. For plan rev 3
   this is a finding against the condition of probe 4.1 that "an `ask` is not approved on its own": after a
   worker restart it was. Only the owner can say whether he tapped anything at that minute.
4. **The harness's own check refused two calls before any prompt**, with the reason "undermining oversight":
   the write of `.claude/guard.local.json` with `rules_off: ["guard-config"]` (the Mac's setting), and a shell
   call that would have fetched Python 3.9 with `uv` and filled `uv`'s cache online. Neither was retried or
   done another way. `host-install` itself stood down, as its `auto` knob says for a cloud session.
5. **Python.** 3.13 with pytest runs offline through `uv run --offline`. 3.12 and 3.11 exist without pytest.
   There is no 3.9, so `g070/suite.sh` gives the 3.13 result only. `ruff` is there.
6. **The tracker does not work.** `tools/tracker/tracker.py show 50` ends with "GitHub GraphQL is not
   available from Claude Code sessions", and `gh auth status` calls the token invalid. Reads and writes of
   issues from a cloud session go through the harness's own GitHub tools, which the tracker does not use. The
   steps `tracker.py review` and `tracker.py new` wait for the Mac.
7. **The after-build checks.** `expect.py`, `expect_files.py`, `caps_pairs.py` and `caps_pairs_ref.py` run
   as they are (the old guard for comparisons comes from `git show e5826b7:tools/guard/guard.py`).
   `heldout_fed.py` gets a `delete-guard` ask: the rule reads the text of a script a command names, and this
   one holds delete forms as data. It needs the owner's tap, or the Mac. The replay needs the Mac.
8. **Silent here.** Run: `git worktree add`, the suite, the checkers, `git add` and `git commit` on this
   branch. Probed against the hook only (point 9): a commit in the worktree, a push of a feature or working
   branch, the first agent start.
9. **Before any new kind of call, probe it.** Feed the hook the event on standard input with
   `KZ_TELEMETRY_DIR` set to a temporary folder and read the verdict. This found the `heldout_fed.py` ask
   before it could stop the session a third time.

## The build: the owner's choice

The build is nothing but edits under `tools/guard/`. Three ways, all his:

- **A. The Mac's setting in the cloud.** He tells the cloud session in his own words to create
  `.claude/guard.local.json` with `rules_off: ["guard-config"]`. The guard asks him once for that write. After
  that a fresh Opus engineer builds steps 3 to 11 there; it reads the brief and the code again. Against it:
  plan rev 3 says `rules_off` is ignored in a cloud session, and the 3.9 run, the replay and the timing need
  the Mac anyway.
- **B. The Mac.** The override exists there and the stopped engineer keeps its context. This is what the
  session recommends.
- **C. A tap per edit.** A few hundred. Not practical.

Not done, on purpose: writing the files through the shell, building under a path the rule does not match, or
using the restart case of point 3. Each would pass the rule this work is about.

What an engineer in a cloud session must be told beside `g080/brief-a.md`:

- `<REPO>` is the checkout, `WT` is `<REPO>/.claude/worktrees/g080-a`, `<SCRATCH>` is a copy of `g080/` and
  `g070/` outside the checkout (the brief forbids temporary files in a checkout; never a copy of
  `g080-heldout/`).
- A call the guard asks about stops the whole session until the owner answers. No delete or force-push words
  on a command line (the brief's rule 5), and no script run by name whose own text holds such words: the
  candidate commands stay in a data file the script reads.
- Only Python 3.13 runs. The brief's rules for 3.9 stay; the 3.9 run happens on the Mac or in CI.
- The cloud harness has a stop hook that reports untracked files; `.claude/worktrees/` is one. Nothing is to
  be committed for it.
